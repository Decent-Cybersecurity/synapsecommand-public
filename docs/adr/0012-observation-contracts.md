# ADR 0012 — Observation payload contracts

## Status

Proposed — 2026-10-15. The four contracts below are implemented in
`packages/cdm/synapse_cdm/observation_contracts.py`, their JSON Schemas are published under
`schemas/observation/`, and their text is `docs/docs/cdm/observation-contracts.mdx`; none of it is
in a release. The contracts are the contract owner's to freeze. This ADR becomes *Accepted* only
when that acceptance is given, and the line then reads in the form of ADRs 0001–0010:
"Accepted — <owner>, <date>, on the private <document>, which is not in this repository". Until
then a field the owner renames is renamed in the models, the schemas and the page in one change,
and the release that would first carry the contracts waits for the acceptance.

## Context

The observation adapters this repository is adding — station text, weather radar, gridded fields,
imagery and product references — need somewhere to put what an environmental measurement or a
model product states: a value with its unit, a grid, a level, quality flags, where in the file the
value is, and the time facts a model run states beside the time it is valid for. The CDM had none
of it. Three facts of this tree decided the shape:

- **The four canonical kinds are complete for this arc.** A fifth kind would reverse a locked
  decision (ADR 0001), falsify the normative sentence that there is no fifth canonical object, and
  red `tests/test_cdm_version_matrix.py`, which holds every frozen contract's file set to `KINDS`.
  The CDM 3.2.0 landing therefore added one `EventType` member, `ENVIRONMENTAL_OBSERVATION`, and
  the optional `Event.validity`, and named an `observation` kind in `MIGRATIONS.md` as the
  successor shape only.
- **A payload model registered in `PAYLOAD_MODELS` binds every producer of its event type.** Four
  classes cannot share one model, and a registration is a schema MINOR that re-stamps every golden.
  The C2SIM adapter's `c2sim-order/1` contract is the precedent for the alternative: a named,
  versioned pydantic model in `Event.payload`, validated by the consumer.
- **`geo.py` has no `crs` field and will not have one**, `Position.alt_m` is metres above the
  ellipsoid only, and check J of the conformance suite walks only keys ending `_at`, `_from` and
  `_to` — not `payload` — so a processing clock in the payload is held by nothing unless its key
  never looks like a time.

## Decision

1. An observation is an `Event` of type `ENVIRONMENTAL_OBSERVATION` whose `payload["observation"]`
   is one of four contracts: `gridded-field/1`, `point-observation/1`, `radar-sweep/1`,
   `imagery-product/1`. Each is a closed, frozen pydantic model in `observation_contracts.py`, and
   a consumer validates with `model_validate` or `contract_of(event)`. Nothing is registered in
   `PAYLOAD_MODELS`, and the contracts add no property, member or definition to the CDM's schemas.
2. The shared blocks: a measurement is `{value, unit, unit_namespace}` with the unit verbatim and no
   unit enum; an unreadable unit or a sentinel is an `Absence` with its mechanism named, never a
   value; the grid is the source's structure, opaque, with no `crs` key at any depth, and the
   canonical geometry is the WGS84 footprint on `Event.geometry`; a level and a datum are carried
   as stated; quality flags are typed and verbatim, or their absence is stated with a basis; a
   locator, discriminated by `kind`, says where in the file; values go by reference, or inline up
   to `MAX_INLINE_VALUES` (4096) with a recorded basis; `product_class` and `product_version` keep
   processing facts out of every key ending `_at`, `_from` or `_to`.
3. Time: `Event.observed_at` is the end of the sensing interval for an observation and the
   reference time for a model product, never a future valid instant; every interval is
   `Event.validity.effective`; the time system a stamp was read in is stated by the source or
   declared by the caller.
4. The station or radar is an `Entity` named in `related_entities`, built by `site_entity`; a time
   the payload does not state is an injected constructor argument (`InjectedTime`), as are a
   station table and request parameters.
5. The contracts' JSON Schemas are published under `schemas/observation/` as a non-union artefact,
   generated by `python -m synapse_cdm.observation_contracts` and held current by its `--check`.
6. One offline host command, `synapse-decode`, reads the file, digests it, checks the digest,
   unwraps a declared container, frames it and constructs the adapter from values, never from a
   manifest row; it refuses remote locators by name.

## Consequences

- A consumer that reads only the CDM's schemas sees an observation as an `Event` with an open
  payload; validating the contract takes the published contract schema or the Python model. If a
  consumer needs the contracts validated by the CDM's schema alone, the `observation` kind named in
  `MIGRATIONS.md` is the successor shape, and it is a separate decision.
- The two validators are not equal (noted 2026-10-15): the published schemas hold shape,
  enumerations, patterns and closed objects, not the models' cross-field rules, non-blank text or
  finite numbers, so a document the schema accepts may still be refused by the model, and only the
  model validates the whole contract.
- A contract changes by a new name (`gridded-field/2`), never in place once accepted.
- Every observation adapter declares a `MAPPINGS` ledger and lists the arrays it leaves in the
  source in a structured limitation, so the preservation ledger classifies them as declared
  limitations rather than as lost.
- The package gains one console entry point, a MINOR by the bump table.

# synapse-link16-bridge: requirement matrix

Written 2026-10-11, when the bridge landed beside the `link16_gateway` adapter. One row per
requirement of the SynapseCommand JREAP C and Link 16 engineering handoff 1.0.0 (REQ001 to
REQ192, 83 ids) and one per row of its acceptance matrix (45 rows), each with the bridge's
evidence and disposition. The translator's half of each row, and the record of the whole arc,
is the repository's `docs/link16-gateway-implementation.md`; a row whose evidence is the
adapter's says "translator" and is dispositioned there.

Test ids are `module::function` under `packages/link16_bridge/tests/`. Disposition words, as in
the record: **PASS** — implemented and tested here; **NOT_RUN** — not run, with the reason;
**BLOCKED_EXTERNAL_EVIDENCE** — needs evidence from outside this repository, with the gate that
unblocks it (the specification's section 18, N01 to N09); **not-claimed** — deliberately not
offered; **maintainer-action** — needs an act only the maintainer can take. No numerical quality
score is given anywhere.

## Deviations from the handoff that the bridge realises

- **REQ003, the name.** The distribution is `synapse-link16-bridge`, imported as
  `synapse_link16_bridge`, not `sc_link16_bridge`: this repository's distributions are named
  `synapse-*`.
- **I03, the operator release.** Besides a provider report at a higher incarnation, an audited
  operator command (`resolve-reuse --decision continue`) releases a quarantined reuse; the
  specification says "await provider resolution". The release holds against the incarnations
  known when it was recorded; a higher incarnation seen later holds the tuple to the rule again.
- **REQ105, the reporting-authority half.** Notices carry no reporter, so the authority half of
  a drop cannot be checked: not claimed.
- **The cursor's "inclusive contents after".** Read as strictly after the committed cursor.
- **The configuration's `cdm_schema_version` default.** The specification's 4.0.0 target is CDM
  3.1.0 here, and the list must be explicit.
- **The transport allowance of section 15.** Its own key, `transport_allowance_seconds` (default
  2), so that `connect_timeout_seconds` keeps REQ061's 5; the request deadline must exceed long
  poll plus the allowance (25 > 22).
